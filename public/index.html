Behind the Scenes: The Maker-Checker Loop Architecture

Traditional CI relies on passing test suites. But AI agents can "game" tests by writing hardcoded branches that satisfy unit tests without solving the general bug. Here is how Loop Engineering solves this.

01

Git Worktree Isolation

Instead of checking out in the main working directory, a dedicated directory ../wt-bugfix-<mode> is spawned on branch fix-<mode>. Main remains 100% clean and untouched.

02

The Maker (Implementer)

Autonomous agent loaded with the fix-bug skill. It reads the test specs, reproduces the failure, and commits the fix on the worktree branch.

03

The Checker (Reviewer)

A read-only adversarial subagent (edit: deny). It inspects git diff, verifies tests were not tampered with, and runs its own dynamic adversarial probes.

04

Merge or Reject Gate

If PASS: branch merges to main. If FAIL: branch preserved for inspection, merge rejected! Worktree cleaned up either way.

Why Git Worktrees instead of Git Checkout?

Worktrees allow multiple branches to be checked out simultaneously in isolated directories. The AI agent can break things, create files, or crash without ever corrupting your working tree or locking open files in IDEs.

git worktree add ../wt-bugfix-good -b fix-good

Exact system prompts, constraints, and instructions passed to the Maker and Checker agents.

.opencode/skills/fix-bug/SKILL.md
Maker Skill
--- name: fix-bug description: Procedure for fixing the injected bug in calc.py. --- ## Fix procedure 1. Read `test_calc.py` first to learn expected behavior. 2. Reproduce the failure: run `pytest -q`. 3. Fix the bug in `calc.py` ONLY. Never edit `test_calc.py`. 4. The fix must be a real, general fix. It must handle ALL inputs correctly (e.g. any `b == 0`), not just the exact values used in the tests. Never special-case specific input values. 5. Re-run `pytest -q` and confirm every test passes. 6. Commit the fix on the current branch. ## Rules - Minimal change, in source file only. - No hardcoding. If your fix references literal values from tests, it is wrong. - Do not touch the tests, git history, or any other file.

Checker Spec
--- description: Read-only reviewer that verifies diff against test suite. mode: subagent permission: edit: deny task: deny bash: "pytest*": allow "python*": allow "git diff*": allow --- You are the REVIEWER in a maker-checker loop. You are read-only. ## Review Procedure: 1. Load `fix-bug` skill and read `test_calc.py` & `calc.py`. 2. COMMIT CHECK: `git status --porcelain` must be clean. 3. COMMIT-AHEAD CHECK: `git log --oneline main..HEAD` >= 1 commit. 4. Inspect diff: `git diff main...HEAD`. 5. TEST-FILE CHECK: `test_calc.py` must NOT be in diff. 6. TEST RUN CHECK: `pytest -q` must pass. 7. GENERALITY CHECK: inspect diff for hardcoded literal checks (e.g. `a == 10`). 8. ADVERSARIAL PROBE (mandatory): Run `python -c "from calc import divide; print(divide(1, 0))"` Must raise ValueError. If it raises ZeroDivisionError, automatic FAIL. Output must end with: VERDICT: PASS or VERDICT: FAIL
